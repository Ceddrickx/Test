1 — dict_Codes (lines 9–13)
system.py — lines 9–13 The promo code dictionary — constant, never changes at runtime
system.pyclick any line to explain
Syntax: dictionary literal{ key : value, key : value } — curly braces wrap it, colon separates key from value, comma separates pairs.
Why outside the class?It's a module-level constant — shared by the whole file. All methods in NUmart can use it directly by name without self.
Key typeKeys are strings ("SAVE10"). When you do code in dict_Codes, Python checks if that string is a key. Values are integers (the discount %).
Lookup speedDictionary lookup is O(1) — instant, no matter how many entries. No loop needed to find a key.
2 — apply_promo() (lines 206–222)
system.py — lines 206–222 Validates and applies a promo code. Returns True or False.
system.pyclick any line to explain
Two-layer promo guardLayer 1: check self.promo_used (not empty = already applied, block it). Layer 2: check code in dict_Codes (not found = invalid). Both must pass for the promo to apply.
Return value mattersreturn True tells the menu "it worked, stop asking." return False tells the menu "it failed, ask again." The while True loop in main.py uses this.
.strip().upper() — why both?.strip() removes accidental spaces. .upper() converts to uppercase. So " save10 " → "SAVE10" and matches the dictionary key correctly.
Two things set at onceself.discount stores the number (e.g. 15). self.promo_used stores the code name (e.g. "STUDENT15"). Both are needed — discount for math, promo_used for display and the guard check.

4 — get_final_total() (lines 233–238)
system.py — lines 233–238 The math engine — returns 3 values: subtotal, discount amount, final due.
system.pyclick any line to explain
Live math example — STUDENT15 on ₱200 cart
total = cart.compute_total()Loops through every item in the cart: price × qty per item, then adds them all. Result: ₱200.00
discounted = 200 × (15 / 100)15 / 100 = 0.15  →  200 × 0.15 = 30.0  →  ₱30.00 deducted
final = 200 − 30₱170.00 — what the user actually pays
Why return 3 values?display_price_summary() needs all 3 to show the breakdown. process_payment() needs final for Amount Due. _generate_receipt() needs all 3 for the receipt. Returning once avoids recomputing.
What if discount = 0?discounted = total × (0/100) = 0. final = total − 0 = total. No discount applied, math still works correctly.
# Interactive demo — change these values mentally: total = 200.00 # cart.compute_total() result discount = 15 # self.discount (STUDENT15) discounted = 200 * (15 / 100) # → 30.0 final = 200 - 30 # → 170.0 return 200.0, 30.0, 170.0 # → tuple of 3 values
